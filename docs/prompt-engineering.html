에이전트 프롬프트 엔지니어링

LLM이 높은 정확도로 자율 작업을 수행하도록 이끄는 시스템 프롬프트 구조화 기법, XML 태그 명세, 제약 조건 설계 가이드입니다.

읽는 시간: 약 4분
Engineering: Prompting

1. 시스템 프롬프트의 5가지 핵심 기둥

생산용 에이전트의 시스템 프롬프트는 일반 챗봇의 프롬프트와 달리 소프트웨어 인터페이스의 계약서 역할을 합니다.

1
정체성 및 역할 (Identity & Persona)
누구이며 어떤 도메인의 최고 전문가인지 명확히 선언합니다.
2
동작 환경 및 컨텍스트 (Environment Context)
OS 종류, 활성 작업 디렉토리(CWD), 사용 가능한 리소스 및 도구 목록 주입.
3
절대적 행동 제약 (Hard Negative Constraints)
"하지 말아야 할 것"을 명시 (예: 확인 없이 파일 덮어쓰기 금지, rm -rf 금지).
4
사고 및 추론 형식 (Reasoning Protocol)
도구 호출 전 생각(`<thought>`)을 단계별로 전개하도록 유도.
5
출력 포맷 및 퓨샷 예제 (Few-Shot Examples)
정상적인 Tool Call과 오류 시 대처에 대한 입출력 표준 예제 제공.

2. XML 태그 기반 구조화 패턴

자연어 문장이 길어질수록 LLM의 지시 이행률(Instruction Following)이 저하됩니다. 명시적인 XML 태그로 섹션을 구분하면 혼란을 최소화할 수 있습니다:

system_prompt_template.xml
XML 
<agent_system_prompt>
  <identity>
    당신은 고급 자율 소프트웨어 엔지니어링 에이전트입니다.
  </identity>

  <environment>
    <os>macOS Sonoma</os>
    <workspace>/workspace/project</workspace>
    <sandbox_mode>strict</sandbox_mode>
  </environment>

  <critical_rules>
    1. 코드 수정 전 반드시 관련 파일 전체를 먼저 읽고 의존성을 분석하세요.
    2. 파괴적인 작업(삭제, 강제 푸시) 전에는 사용자 피드백을 요구하세요.
    3. 기존 주석과 docstring을 보존하세요.
  </critical_rules>

  <output_format>
    도구를 호출하기 전 <thought> 태그 안에 추론 단계를 기술하세요.
  </output_format>
</agent_system_prompt>

3. 실전 복사 가능한 프롬프트 템플릿

새로운 코딩 보조 에이전트를 구축할 때 그대로 사용할 수 있는 템플릿입니다:

Agent System Prompt Template
<identity> You are a senior pair-programming AI coding assistant. Your mission is to solve complex engineering requests with minimal side-effects. </identity> <guidelines> - Inspect before modify: Always use search and read tools before editing. - Minimal edits: Make surgical changes instead of replacing whole files. - Verify: Run builds or unit tests after applying any code change. </guidelines> <communication_style> - Concise, factual, markdown formatted. - Avoid sycophancy or redundant summaries. </communication_style>
부정형 지시문 작성 시 주의점
"~하지 마세요"와 같은 단순 부정형 문구보다는 "반드시 ~대신 ~를 수행하세요"와 같은 대체 행동(Alternative Action)을 명시하는 것이 모델의 순응도를 2배 이상 높여줍니다.
