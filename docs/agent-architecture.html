AI 에이전트 아키텍처

자율 에이전트 시스템을 구성하는 핵심 추론 루프(Percept-Reason-Act), 계층형 메모리 구조, 그리고 멀티 에이전트 조율 패턴에 대한 심층 기술 문서입니다.

읽는 시간: 약 5분
System: Architecture

1. 핵심 실행 루프 (Percept-Reason-Act)

AI 에이전트는 단순한 단발성 텍스트 완성을 넘어, 목표가 달성될 때까지 환경과 능동적으로 상호작용하는 유한 상태 머신(Finite State Machine)의 특성을 갖습니다.

단계 (Phase) 역할 및 동작 주요 산출물
Perception (인식) 사용자 입력, 파일 시스템 상태, 도구 실행 결과, 터미널 로그 수신 원시 데이터 정규화 & 컨텍스트 버퍼 적재
Reasoning (추론/계획) 현재 상태와 최종 목표 간의 차이를 비교하고 다음 최적 행동 결정 사고 과정(Chain-of-Thought) 및 도구 호출 파라미터
Action (실행) API 호출, 셸 명령어 실행, 파일 생성/수정 등 환경에 영향 행사 Tool Call 실행 및 종료 코드
Observation (관찰 & 평가) 실행 결과의 오류 여부 분석 및 오류 시 자체 복구(Self-Correction) 전략 수립 다음 턴의 인식 입력으로 피드백
루프 종료 조건 (Termination Criteria)
무한 루프 방지를 위해 (1) 최대 턴 수 제한(Max Turns), (2) 목표 달성 검증 신호(Done Signal), (3) 예산/토큰 한도(Token Budget)를 항상 설정해야 합니다.

2. 에이전트 메모리 계층 구조

대용량 컨텍스트 윈도우를 효율적으로 활용하기 위해 메모리를 3가지 계층으로 분리하여 관리합니다:

단기 작업 기억 (Working Memory)
현재 대화 세션의 직전 대화 기록 및 활성 상태의 Tool Result 목록입니다. 실시간 추론 시 슬라이딩 윈도우 방식으로 유지됩니다.
스크래치패드 & 아티팩트 (Scratchpad)
단계별 계획서, 가상 파일 버퍼, 중간 계산 결과 등을 보관하는 지속 가능한 아티팩트 영역입니다. 대화 토큰을 절약합니다.
장기 지식 메모리 (Vector Store / RAG)
과거 해결 이력, 코드베이스 전체 인덱스, 대규모 레퍼런스 문서를 임베딩 기반 검색(Similarity Search)으로 추출합니다.

3. 다중 에이전트 (Multi-Agent) 조율 패턴

복잡한 대규모 엔지니어링 문제를 해결할 때 단일 에이전트보다 전문화된 하위 에이전트(Subagents) 팀을 구성하는 것이 효율적입니다:

오케스트레이터 패턴: 메인 관리자 에이전트가 전체 목표를 세부 작업으로 분할하고, 각각의 전문 에이전트(예: 리서처, 코더, 테스터)에게 비동기 위임합니다.

orchestrator.json
JSON 
{
  "orchestrator": "LeadPlannerAgent",
  "delegates": [
    { "role": "code_search", "agent": "ResearchAgent", "mode": "read-only" },
    { "role": "refactor", "agent": "CodingAgent", "mode": "sandbox-write" },
    { "role": "verify", "agent": "TestRunnerAgent", "mode": "isolated-test" }
  ]
}

생성기-비평가(Generator-Critic) 패턴: 초안을 작성하는 에이전트와 보안/품질 기준에 따라 엄격하게 검증하는 비평 에이전트가 교차 피드백을 통해 결과물의 완성도를 극대화합니다.

장점
취약점 탐지율이 비약적으로 증가하며 코드 환각(Hallucination)을 90% 이상 사전 차단할 수 있습니다.

순차 파이프라인 패턴: 작업의 입출력이 명확할 때(분석 → 설계 → 구현 → 배포) 각 단계의 출력이 다음 에이전트의 입력으로 직접 전달되는 구조입니다.

4. 상태 전이 및 에이전트 라이프사이클

시스템 안정성을 유지하기 위해 에이전트는 다음과 같은 표준 상태(Lifecycle State)를 전이합니다:

1
IDLE → READY
사용자 요청 수신 후 시스템 프롬프트, 도구 스키마, 컨텍스트 주입 준비 완료 상태.
2
RUNNING (추론 & 도구 실행)
LLM 호출 및 도구 실행을 반복하는 활성 루프 상태. 실시간 이벤트 스트리밍 발생.
3
WAITING_FOR_FEEDBACK / BLOCKED
보안상 중요 작업(예: 프로덕션 배포, 파일 삭제) 전 사용자 승인을 기다리거나 외부 이벤트 대기.
4
COMPLETED / TERMINATED
목표 완수 후 산출물 정리, 워크스페이스 정리 및 최종 리포트 출력.
